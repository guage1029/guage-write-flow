# style-guide.md — 写作风格规范

> 本文件固定 Markdown 标题语法与瓜哥口语声线，不固定章节主题和叙事顺序。作者画像与用户本次要求优先；事实准确性始终优先于口语和传播效果。

## 固定 Markdown 格式

完整长文按以下标题层级输出。固定的是格式，不是章节主题：

```markdown
# 主标题

可选副标题（普通段落，不使用标题标记）

开篇正文，不另设“引言”标题。

## 主要章节

### 需要时使用的子章节

#### 仅在确有必要时使用，并按同一父级连续标记 ①、②、③……
```

- 全文恰好一个 `#` 主标题；完整长文至少一个 `##` 主要章节。
- 主要章节使用 `##`，子章节使用 `###`；`####` 仅在信息确有层级时使用，且按同一父级连续编号。禁止 `#####` 和更深层级，不跳级。
- 开篇可以直接进入故事、问题或结论，不加“引言”；结尾按内容命名或自然收束，不固定叫“写在最后”。
- 标题文字随本篇内容确定，不使用固定的“背景 / 原理 / 总结”章节模板。

## 瓜哥声音校准

把 `persona.md` 中的作者声音作为新写文章的强制默认目标，尽可能贴近瓜哥自然口语。不能满足于“清晰但像通用技术说明”；按本篇材料和文章类型选择讲述方式，不套同一套开头、章节或口头禅。

- **先找到本篇的抓手**：读者在意的问题、作者真实做过的事、一个有分量的结果，或一个需要拆开的说法。开篇尽快给出其中一项，再交代本文要解决什么；顺序按材料决定。
- **让作者通过真实动作出现**：写清作者测试、观察、筛选或取舍了什么。若素材没有作者亲历，就用直接的解释者视角，不补写“我试了”“我发现”等经历。
- **用“场景 / 证据 → 解释 → 判断”推进**：实测类可让案例逐步加难；更新盘点要说明取舍依据；教程围绕读者任务讲清操作和结果；经验复盘讲决定、代价和边界。不强求全部文章都用案例叙事。
- **把判断说出来并限制范围**：少用空泛中性转述。说明证据支持什么、不能说明什么；标题的数字、动词和强语气都必须在正文兑现。
- **保持自然口语和技术准确**：句子直白，术语需要时就地解释；允许短促评论、反问或生活化补充，避免刻意造梗、密集感叹和整齐的宣传句。
- **读起来像当面讲给读者听**：优先主动句、常用词和自然停顿；发现书面连接词、被动套句或翻译腔时改成作者会自然说出口的表达。口语化不等于每段加第一人称或口头禅。
- **结尾留下本篇独有的落点**：可以给适用边界、下一步建议、作者判断、真实生活感受或后续问题。账号介绍、关注邀请、预告和“写在最后”只在确有作用时使用。

**输出前自检：** 去掉强形容词、加粗和口头禅后，文章是否仍有清楚的问题、真实材料或可核验依据、作者自己的判断？若没有，先补清内容依据或收窄判断；不要用第一人称和金句伪造作者声音。

**阻断规则：** 新写长文的口吻校准与 Markdown 格式清单必须全部通过才可交付；任一项不通过就先改稿。AI 风格 P0 必须清零，P1 必须改成自然、具体的表达；不能以脚本未命中作为免审理由。

**风格与事实分开：** 不照搬样文中的事实、经历、错误或夸张程度。现有文章要求降 AI 味时，优先保护原作者表达，除非用户明确要求改写成瓜哥口吻。

## 结构与节奏

- 先选能承载材料的叙事顺序，再决定标题层级。不要为了满足固定模板，把每段都切成小节。
- `#` 用于整篇标题；`##` 划分主要内容段；`###` 仅在确实有助于定位和扫读时使用；`####` 默认少用。层级连续、语义清楚即可；若使用 `####`，标题开头按同一父级下的顺序使用 `①`、`②`、`③`、`④`……。
- 开篇可以先放作者、背景、核心问题、关键示意图或结果摘要，按读者理解顺序安排，不强制先目录或先表格。
- 步骤用有序列表；多项数据确实需要横向比较时用表格。表格不是所有评测文章的必备项。
- 结尾回到正文证据，给出作者判断、适用范围或读者下一步。标题可用“写在最后”，也可按内容命名；不强制固定结尾标题或上手清单。

## 段落、句子与强调

- 以手机端好读为目标。短段落是常用节奏，但句长、段长随内容变化；不按固定字数切句。
- 一段尽量围绕一个主要意思。操作步骤、解释和个人判断可以各自成段，长段只在推理连续时保留。
- 加粗只标出关键判断、术语或读者需要扫到的信息，不要求每段加粗，也不为格式凑重点。
- 口语要像作者自然说话，不靠堆语气词、网络词、感叹号或夸张形容词制造“人味”。
- 可用“说实话”“小结一下”等作者常用表达，但只在语境自然时使用，不作为模板填充。
- 新写长文必须经过口语化朗读检查；仍像通用 AI 说明文时，重写相关句段后再交付。

## 证据与表达边界

- 区分日志事实、实测结果、个人推断和一般结论，并写清测试范围。
- 没有同题基线，不比较快慢、准确率或优劣；日志未记录到的结局，不写成已通关或已成功。
- “请求成功 / 返回合法选项 / 完成任务 / 结果更好”是不同层级的结论，不得互相替代。
- 不把口语化当成弱化证据要求的理由。未经验证的结论应缩小范围、加限定或列为待核实。
- 删除空洞套话、机械转场、夸张宣传和无来源归因；保留必要的重复、停顿和自然转折。

## 文章类型参考

以下是可选组织方式，不是必须照抄的模板：

- 实测 / 案例：为什么做 → 自己怎么试 → 由简单案例逐渐增加难度或代价 → 日志说明了什么 → 作者能下什么结论。
- 原理解析：一个具体问题 → 关键机制 → 例子或图示 → 能做与不能做的边界。
- 教程：目标与前置条件 → 操作步骤 → 预期结果 → 常见错误与处理。
- 经验分享：遇到的问题 → 试过的办法 → 结果与代价 → 给读者的建议。

结构应跟着素材走。若案例本身已经形成故事线，优先保留故事线；用承接句解释案例为什么升级或转场，不要再叠一套重复的“背景—原理—总结”。

## 避免的表达

- 助手式开场白、万能总结、空泛的意义拔高和无证据的绝对化结论。
- 为制造悬念而虚构冲突、时间、对话、情绪或人物反应。
- 连续套用“首先、其次、最后”、整齐三段式、每节金句或固定三条结论。
- 把简单事实扩写成教程腔、评测报告腔或产品宣传文案。
- 将作者自然口语统一改写成书面语；也不反向把整篇硬改成网络口吻。
